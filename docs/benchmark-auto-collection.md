# 对标资料自动采集 P0：实现与验收

2026-10-17。代码与隔离测试已实施；真实页面验证部分通过，详情见文末补充。

## 实际链路

推荐按钮不再要求先只给候选、再逐卡核实。所有 agent 提示词均要求在已经打开目标浏览器时就地完成 candidate → verified → 主页与头像 → 最多五篇主页可见笔记 → 收尾，每个阶段独立写检查点。

服务端合并 candidate/verified 后登记账号目录的 `benchmarks/collection.json`。每秒合并已落盘检查点；当前账号有 agent/worker 任务时等待。原 agent 已完成观察则不重复派发；已提交部分观察则暂停并保留原因。其余目标按账号串行派发：已开启且兼容的 worker，或现有 agent 浏览器。目标任务上限 180 秒，错误、能力缺失、登录或风控中止后暂停账号队列。

观察检查点的接收归属通过服务端合并记录识别，不用页面观察时间与服务入队时间比较。身份核实不等于资料采集完成；没有头像、主页字段或已观察的笔记列表时，收尾不能标完整。每篇笔记及头像仍由既有校验器落盘，冲突进入 rejected，缺字段不清旧值。

列表提供账号级「补齐缺失的已登记对标」「暂停队列」「已准备登录，整体继续」，显示已完成、待办、当前目标与原因。暂停允许当前目标收尾。重启时遗留 pending/running 都暂停，用户整体继续后跳过已完成目标。已完成条目后来缺图也可重新批量补齐。没有批量请求时不会扫描全部旧条目打开页面。

## 隔离验证

- `tests/browser-worker-server.test.mjs`：真实 HTTP/SSE 服务 + 假 agent + 模拟 Playwright。一次推荐请求只写候选，真实队列自动核实并保存头像 PNG、主页与两篇笔记；不点击单卡。检查头像文件接口、笔记检查点、SSE、身份冲突、坏头像保留旧图及跨账号流程。PNG 是测试 fixture，**不是小红书真实头像截图**。
- `tests/benchmark-auto-agent.test.mjs`：worker 关闭，真实收件箱任务在同一个任务内按主页、第一篇、第二篇逐步写检查点，每步读取 HTTP 确认落盘；结束后没有重复任务。旧目标一次批量补齐自动转 agent，登录错误使队列暂停。观察字段同样为测试 fixture。
- `tests/benchmark-queue.test.mjs`：六目标串行，第三目标中断，重启暂停，恢复不重采前两个；重复登记去重；跨账号隔离；部分观察不重复派发；pending 重启保护；曾完成后缺图重新补齐。
- `tests/browser-worker.test.mjs` 与检查点测试：仅处理实际可见的 0～4 篇/最多五篇；登录与风险、身份冲突、逐篇取消与超时、租约、损坏检查点与头像回退。
- 在隔离数据目录运行本地工作台，用 ego-browser 实际打开列表、点击批量补齐，并打开详情核对已保存字段及两篇笔记。截图为 [列表](verification/benchmark-p0-list.png) 和 [详情](verification/benchmark-p0-detail.png)。截图中的头像与账号均为隔离测试数据。

## 真实页面验证补充（2026-10-17）

用户授权重启并验证一个已登记目标后，先确认 bridge running/pending 均为 0、无在途对话和发布排期，再重启。真实创作者页面使用 `.personal .base` 个人资料卡及“小红书账号”标签，已据此修复登录身份读取；仍不接受正文推荐区中的账号。

实际进入目标主页，完成身份核对和主页资料增量保存。发现真实指标为“数字在前、标签在后”，旧解析会串读下一项数字；已修复并根据当次可见证据通过独立检查点纠正本轮字段。头像在资料区域之外，已调整为唯一可见的头像图片元素，并在截图时恢复可见窗口；此项修正尚未在真实页面复验。

第一篇笔记页面提示“当前笔记暂时无法浏览，请打开小红书App扫码查看”。已停止进一步真实访问并暂停采集队列，没有尝试绕过或改用其他链接。成功笔记数 0，头像尚无有效截图，目标保持 partial。故真实验证仅通过登录身份、目标主页与资料落盘，**头像和五篇笔记全流程仍未通过**。后续需本人处理平台提示后继续验证。
