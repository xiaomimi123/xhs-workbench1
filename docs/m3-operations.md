# M3 运营自动化：发布排期 · 评论私信 · 数据复盘

> 状态：已实现（v0.3.0），已在真实测试账号上完成全流程验证（2026-10-15）。

## 目的

把内容生产之后的日常运营交给工作台：到点发布、及时回复评论私信、定期看数据复盘，并把结论回流知识库，形成闭环。

## 总体设计

```
            ┌──────────── 本地服务（常驻） ────────────┐
            │  Scheduler：每 30 秒检查一次               │
            │   · 到点的排期 → 提醒 / 交给 agent 发布      │
            │   · 每 N 小时 → 让 agent 检查评论私信        │
            │   · 每天 HH:MM → 让 agent 抓取数据           │
            └───────────────┬────────────────────────┘
                            │ 发到每个账号的「⏰ 自动任务」会话
                            ▼
                 agent 按 playbooks/ 执行，结果写回文件
                            │
                            ▼
            工作台面板 + 顶栏🔔提醒（+ 浏览器系统通知）
```

- **调度器在本地服务里**（`server/automation.mjs` 的 `Scheduler`），不依赖网页是否打开；需要电脑开机、工作台运行。
- **自动任务走普通对话通道**：发到每个账号专属的「⏰ 自动任务」会话，用户随时能在对话面板里看到 agent 做了什么。CLI 模式和收件箱模式都适用（收件箱模式需要 agent 在值守）。
- **结果以文件为准**：agent 按手册把结果写回 `schedule.json`、`engage/items.json`、`analytics/*.json`。任务结束但 agent 没回写时，排期被标记为「待确认」，失败时标记为「失败」，都会出现在提醒里。

## 数据结构（每个账号独立）

| 文件 | 内容 |
|---|---|
| `schedule.json` | 发布排期：笔记、计划时间、方式（`remind` / `auto`）、状态、链接、失败原因 |
| `engage/items.json` | 评论 / 私信：内容、草稿、状态（`new → drafted → approved → sent / failed`，或 `ignored`） |
| `analytics/notes.json` | 每篇笔记最新指标 + 每日历史快照 |
| `analytics/account.json` | 账号级每日数据（粉丝数等） |
| `analytics/reports/*.md` | 复盘报告 |
| `analytics/imports/` | 用户上传的导出表格 / 截图 |
| `automation.json` | 自动化设置（发布频率限制、评论检查间隔、每日抓取时间）和运行记录 |

字段定义见技能包 `playbooks/publish.md`、`engage.md`、`analytics.md`。

## 关键设计与取舍

### 发布：默认「提醒 + 手动发布助手」，自动发布可选
自动发布风险最高（不可撤回、平台风控、页面改版导致误操作），所以：
- 默认方式是**到点提醒**：顶栏铃铛 + 浏览器系统通知，排期页展开「手动发布助手」——复制标题、复制正文 + 话题、下载封面、打开创作者中心、回填链接。人工发一篇大约 30 秒。
- **自动发布**需要显式选择，并要求 agent 有浏览器控制能力；手册规定遇到登录、验证码、风控提示、不确定是否已发出时一律停止并标记，**绝不重复发布**。
- **频率限制**在服务端强制：每日上限（默认 3 篇）、两次发布最小间隔（默认 60 分钟）、同一篇笔记不能重复排期。
- **错过保护**：超过计划时间 2 小时仍未执行（如电脑休眠）的排期标记为「已错过」，不会补发，由用户决定。

### 评论私信：默认人工确认
agent 只起草，用户逐条确认后点「发送已确认的 N 条」才让 agent 发送，且必须原样使用草稿。草稿实时套用违禁词检查（站外引流等）。用户可以在设置里改为自动发送，并限制每次条数；手册要求发送间隔 10-30 秒、遇到风控立即停止。

### 浏览器控制：两种接入方式
CLI 模式下 agent 无法弹窗请求授权，需要预先放行浏览器工具。`workbench.mjs browser-setup` 提供：
- **Playwright MCP**（默认）：独立浏览器资料目录，首次由用户在 agent 打开的窗口登录；版本在配置时用 `npm view` 查询后锁定。
- **Claude in Chrome**：复用用户日常 Chrome 的登录状态，需要浏览器扩展。

命令默认只打印将要做的修改，加 `--yes` 才执行，并跑连接测试，失败则保留原配置。收件箱模式的 agent 用它自带的能力，无需配置。

### 数据：抓取 + 导入双通道
能控制浏览器就直接读创作者中心；不能就让用户从创作者中心导出表格 / 截图上传到「导入数据」，agent 解析后合并。指标允许写成"1.2万"这类字符串，前端统一换算。

### 图表
趋势图是单序列折线（无图例，标题即说明），2px 线 + 10% 面积填充 + 末端数值标注，悬停显示十字线和读数；刻度按 1/2/5 取整。线条颜色用品牌红，浅色 / 深色模式各自经过 dataviz 校验脚本验证（`#ff2442` / `#ff3d5a`）。

### 真实账号测试（2026-10-15，测试账号，Claude Code CLI + Playwright MCP）

| 场景 | 结果 |
|---|---|
| 登录 | ✅ agent 打开创作者中心后在登录页等待，用户本人扫码登录，约 45 秒后检测到登录成功；之后每次重新打开浏览器都保持登录状态 |
| 抓取数据 | ✅ 读取 9 篇笔记和账号近 30 天的每日数据并写入 `analytics/`，全程只读；数据复盘面板显示正常 |
| 检查评论私信 | ✅ 抓到 8 条，其中 5 条起草了回复，3 条按规则忽略（单字、纯表情、广告），没有发送；私信只读会话列表预览，没有点开会话，避免被标为已读 |
| 定时自动发布（仅自己可见） | ✅ 调度器按时触发；agent 依次检查素材、核对登录账号、上传封面、填写标题 / 正文 / 话题、设置仅自己可见、核对后发布，在「笔记管理」查到链接后回写 `schedule.json` 和笔记状态；用时约 2 分钟，没有出现风控提示 |
| 发送评论回复 | ✅ 用户选定并确认 1 条草稿后，agent 打开对应笔记，先确认之前没有回复过这条评论，再点「回复」、原样输入草稿；发送后在评论区看到带「作者」标识的回复，并通过网络请求确认回复对象正确，然后把状态改为 `sent`；其他条目没有改动 |

测试过程中修复的问题：
- Playwright 的页面快照和网络数据（含账号信息）原先存在数据目录根部，现改到 `run/browser-output/`。
- `account.json` 中每日数据的含义（当天新增还是累计）原先没有写清楚，手册已补充，图表标题也会注明。
- 新增笔记「可见范围」字段（公开 / 仅自己可见），发布手册要求找不到这个设置时停止发布，不能以公开方式发出。
- 评论手册要求不要逐个点开私信会话。
- 发布手册补充了实测得到的页面经验（Shadow DOM 里的发布按钮、话题选择方式等）。

## 已知限制

- 回复只测了评论，私信回复还没有测过；批量回复的间隔与风控表现也还没有验证。
- 自动发布只测了一次「仅自己可见」的图文笔记；公开发布、多图、视频笔记还没有测过。
- 放行的 Playwright 工具中包含 `browser_run_code_unsafe`（在页面里执行脚本）。这次发布时用它处理了 Shadow DOM 里的发布按钮；它只能作用于浏览器页面，不能访问本机文件。
- 创作者中心页面改版会影响 agent 的操作；手册只描述目标和成功标准，不依赖具体元素选择器，但仍可能需要用户介入。
- 定时任务依赖电脑开机和工作台运行；暂不支持开机自启。
- 重新运行 `bridge-test` 会重置 agent 参数，需要再运行一次 `browser-setup`。
