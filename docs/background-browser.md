# 后台有头只读采集与模型路由

## 目的与范围

对标主页的 URL、昵称、小红书号、头像和部分指标是可见页面字段。旧流程每次让 agent 重新打开 Playwright MCP 浏览器、反复调用模型读页面，既慢又可能抢占桌面。本功能只把**单个对标账号的主页核实、头像元素截图和最多 5 篇主页可见笔记的原始字段**交给本地持久浏览器工作进程；候选推荐、规律拆解、爆款雷达的新笔记检查、发布、评论和其他 agent 任务仍走原通道。身份不明确时不写“已核实”。

## 启用与使用

1. 先按现有流程运行 `browser-setup`，配置 CLI 模式、有头 Playwright MCP，并在账号管理填写当前账号的**小红书号**。收件箱模式、Claude in Chrome 和已选无头模式不会被偷偷切换。
2. 用户确认后运行 `node xhs-workbench/scripts/workbench.mjs browser-worker-setup --yes`；可先不带 `--yes` 查看变更。只在本机数据目录的 `browser-runtime/` 安装锁定版本 `playwright-core@1.64.1`，基础工作台无需安装第三方依赖。`browser-worker-status` 查询安装与启用状态。设置页可关闭/重新开启后台读取；关闭时释放工作进程的窗口，不删除登录资料。
3. 在「竞品对标」打开一个账号，点击「补齐头像和主页数据」或「刷新主页与近 5 篇笔记」。有头窗口首次出现时由用户本人登录/扫码；如出现验证码、访问限制、操作频繁，停止抓取并保持窗口可见。登录后需要在创作者中心**实时读到唯一的小红书号**，且与当前账号设置一致；旧的 `browser.json` 只能作历史展示，不能代替此次核验。无法读到时请用原 agent 路径或人工核实，不猜账号。
4. 核对成功后尝试 Chromium CDP 最小化，不主动置前、不用系统鼠标/键盘。后台加载超时只重试一次并恢复可见窗口；最小化失败则显示“可见有头模式”；恢复失败会提示从任务栏或 Dock 手动打开窗口。窗口最小化不等于无头，也**不能保证完全不抢焦点或规避平台风控**。

## 资料租约、数据与模型

- 资料位于 `browser-profiles/<工作台账号id>/`。工作进程按账号惰性启动并复用一个页面；同账号的 MCP CLI 任务先等待当前只读任务结束，再关闭工作进程并等待资料释放，然后才启动 agent。不同账号可并行。其他外部进程占用资料时拒绝启动，绝不删除 `SingletonLock`（包括悬空符号链接）、复制 Cookie 或静默改用临时资料。工作台退出时关闭其工作进程；下次任务重新打开资料。
- 只读器固定访问小红书创作者中心、一个候选的站内搜索页（如没有主页链接）、一个主页及该主页当前可见的最多 5 个站内笔记链接；不接受调用方提供的任意脚本、选择器或目标站点，不点赞、不关注、不评论、不发布。主页需为 HTTPS 小红书用户主页，笔记需为限定的站内链接。头像来自头像元素局部 PNG 截图而非整页快照。需要唯一匹配的搜索结果；同名、结构变化、身份不符、字段缺失或风险提示均返回“需复核”或保留已保存部分并说明原因。核实任务上限约 180 秒，页面加载和重试次数有界，取消后关闭窗口再交接资料。
- 已核实结果以独立的 `<id>.verified.json` 检查点原子写入 `benchmarks/checkpoints/pending/`，立即校验合并；主页及逐篇笔记观察以 `.observation.json` 检查点增量保存到独立 `snapshot.json`，每个字段保留原观察时间/来源，缺失字段不编造 0。`verificationSource` 只记录主页 URL 与字段名，**不保存页面快照、Cookie 或验证码**。agent 备用路径使用不同文件名逐篇保存相同观察结构；见 [竞品对标卡片与原始观察](benchmark-observation.md) 和 `xhs-workbench/playbooks/benchmark.md`。现有用户手填字段、删除墓碑、同号冲突与残缺文件保护不变。服务重启仍按检查点恢复。
- 确定性读取 **零次模型调用**。仅当搜索结果有歧义且用户在设置页为 Claude Code CLI 明确填写快速模型时，另起一次 `--tools "" --no-chrome --no-session-persistence --strict-mcp-config` 的短文本调用，输入限量候选字段；它只提供人工复核建议，**不能单独产生核实检查点**。不支持指定模型的其他 CLI、收件箱模式保持原行为。正常写报告、发布和评论继续用原模型；CLI 对话续接还必须匹配账号、适配器和模型档位；只读任务之后会重新组装包含核实结果的上下文，不直接续接旧 agent 会话。

## 验证与边界

`npm test` 在临时数据目录用假浏览器/假 agent 测核实与观察检查点、头像校验、最多五篇、HTTP/SSE、无模型读取、资料租约、多账号、取消/超时、外部锁及最小化失败。模拟测试不能替代真实平台验证：页面结构可能变化，保守返回需复核；本地 macOS 的可见窗口体验与 Windows Edge 的窗口/焦点、手工登录、发布/评论交接需要分别实测。**Windows 真机验收未完成时不能宣称无干扰**。默认不安装/不开启时，用户仍可用 agent 单账号观察检查点路径，其他功能不受影响。旧对标不会自动批量抓取头像或笔记。
