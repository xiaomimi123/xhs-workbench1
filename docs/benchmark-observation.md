# 竞品对标卡片与原始观察

## 目的与用法

竞品对标列表以目标账号头像、主页核实状态和可见数据覆盖情况展示卡片；打开卡片默认进入「主页数据」，分别展示主页资料与最多 5 篇**主页可见笔记**。这里是页面观察，不是按时间确认的最近五篇，也不等于 agent 的爆款规律报告。旧条目没有采过头像时只显示文字占位；推荐/核实流程自动采集；旧数据通过账号级批量补齐，单卡刷新仅作为可选操作。不能从旧的粉丝数字推造头像、简介或笔记。

优先使用设置页**明确开启**的可选后台有头只读组件（默认关闭）。它在单个账号下核对当前登录账号与目标主页身份，截取头像**元素的局部 PNG**，读取可见主页指标和前 5 个不同笔记链接，逐篇只读访问；确定字段不调用模型。组件关闭、不兼容或用户选择「改用 agent」时按 `xhs-workbench/playbooks/benchmark.md` 的同一观察合同写检查点。登录、验证码、风险提示由用户本人处理；抓取不能保证不影响电脑焦点，也不能规避平台限制。自动发布、自动评论、多账号、原有 agent 爆款雷达与深度拆解不受影响。

## 数据与写入顺序

- 每个工作台账号单独存放在 `accounts/<账号id>/benchmarks/`。列表 `index.json` 保存用户手填资料、身份核实及追踪设置；页面原始观察在 `<对标id>/snapshot.json`；原 `notes.json` 和 `report.md` 分别给 agent 拆解/雷达、报告使用，绝不把观察自动标成已拆解。
- 先核实主页，写 `<id>.verified.json`，再写主页观察与每篇笔记检查点，最后写 complete/partial/unavailable 状态。服务按文件名合并完整的 JSON；worker 立即合并、广播 SSE，agent 按批次用不同文件名逐篇保存，避免尚未合并时覆盖上一步。服务重启会重放 `pending/` 的有效文件；冲突进入 `rejected/` 并留 `.reason.txt`，残缺 JSON 留在 `pending/` 等待完整写入。
- `snapshot.json` 记录已核实主页 URL/小红书号、昵称、观察时间/来源、资料字段、最多 5 个笔记链接及各自可见字段、状态/失败原因。字段形如 `{ "value": "12", "observedAt": "2026-10-17T05:00:00.000Z", "source": "worker-visible" }`；agent 来源为 `agent-visible`。缺失字段不填 0，新检查点只覆盖本次实际读到的字段，旧值保留**旧观察时间**。笔记按 URL 合并，最多保留 5 条；有旧值时详情展示的是积累的观察，不表示每条都在本次重新读到，查看每条的时间。`profile` 是初步落盘状态，`partial` 表示有中断/缺口，`complete` 仅表示本次选取的可见笔记已经走完，`unavailable` 表示本次无法读到列表；页面某些指标未展示时仍为空。
- 头像截图先保存为 `<对标id>/avatar-source-*.png`，检查点校验后复制到 `avatar-captured-*.png` 并暴露本地文件路径。只接受不超过 2MB、2048×2048 的 PNG，拒绝站外路径、跨账号文件和符号链接；截取失败不清除旧头像。用户上传的 PNG/JPEG/WebP 以 `avatar-manual-*` 独立保存并标注手动来源。显示优先页面截图，其次手动图，最后文字占位。文件通过带令牌的账号隔离接口读取，页面不直接引用未经核验的远程头像地址。

## 校验与边界

服务核对对标 id、当前列表是否存在、主页 URL 与已核实小红书号是否一致、ISO 时间、来源、字段长度、笔记域名与数量、PNG 格式和头像所在目录。相冲突的检查点不覆盖旧观察；删除条目时墓碑阻止旧检查点复活它。任务超时/取消只保存已完成的检查点，未写入的页面观察不能恢复。登录资料不复制、不删浏览器锁、不自动切无头；新任务约 180 秒，故部分笔记受限/选择器不匹配时会显示原因，而非造数据。

`npm test` 覆盖纯解析、临时数据目录的检查点、模拟浏览器/API/SSE 及跨账号/删除保护。模拟测试**不等于真实小红书页面可用**：头像与笔记 DOM 可能变化，需在获准的真实页面复核；Windows Edge 的窗口、焦点和登录仍需 Windows 真机验收。旧数据通过账号级「补齐缺失的已登记对标」一次加入有界串行队列；未准备登录时不静默批量打开页面。
