# 评论私信：历史整理与本地回复审核

## 使用与边界

「评论私信」顶部的「历史消息整理与本地审核」使用已保存的消息，支持按类型、历史状态、来源笔记筛选，选中后生成整理和回复草稿。原来的正式操作保留在独立折叠区。

- 新结果保存在账号目录 `engage/reply-jobs/`，原 `engage/items.json` 不改动；历史已忽略和已回复消息不会重新进入待发送队列。
- 原消息、原回复与可用笔记上下文冻结为 `.input.json`。按规范化笔记 URL 关联历史数据，仅标题/指标时明确不是全文，不从指标推断教程或效果。
- 共享品牌口径仅作参考；历史回复也不是事实证明。Agent 只写 `.result.json`，服务端校验消息覆盖、引用、重复、长度和结构后保存审核结果。
- 私信标注为已有预览，信息不完整，不自动打开会话。重复候选只提示，不删除旧数据。
- 记录分类、建议处理方式、草稿及待核实事项。分类与建议仍需本人审核，词表提示不代表平台审核结论。
- 本地编辑保留版本历史；空草稿不能确认。确认绑定具体草稿版本及原消息指纹，编辑保存自动撤销旧确认，原消息变化会让旧确认失效。
- 确认只写 `confirmed_local`，固定 `nonExecuting=true`，不写原队列的 approved/sent，不分派发送任务。支持撤回，撤回后保留草稿。
- 未保存文字按账号保留，刷新和筛选不丢失；保存/确认/撤回请求期间继续输入也保留文字，并同步服务器返回的新版本。
- 任务支持失败、重试、去重与重启恢复；未产出或伪造来源不会显示完成。

用户要求的演示由 Agent 在本地点击确认控件，验证状态流转；这不表示用户已经逐条审核这些回复文字。演示结束撤回所有确认，新草稿保留。
