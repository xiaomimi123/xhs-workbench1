# v0.5 增强：视频笔记 · 对标追踪雷达 · 历史笔记导入 · 新手引导

> 状态：设计中（2026-10-15）。四项均已确认要做。

v0.4 补齐了可靠性和多账号；v0.5 解决三件事：**内容形式缺口**（视频）、**运营闭环常态化**（对标从一次性拆解变成持续追踪）、**新用户冷启动**（历史数据导入 + 首次引导）。

## 1. 视频笔记支持

**现状**：笔记只有图文（`meta.media = [{file, video?}]`，`video` 是实况图的动态配对视频）。小红书上视频流量占比高，这是内容形式上最大的缺口。

**数据设计**：`meta.json` 新增可选字段 `video`：

```json
{ "video": { "file": "demo.mp4", "cover": "video-cover.jpg" } }
```

- `file`：`notes/<id>/images/` 里的视频文件（mp4 / mov，与实况图共用目录和上传通道）。
- `cover`：可选，封面文件名（也是 `images/` 里的静态图）。三种来源优先级：`video.cover`（用户显式指定，浏览器截帧或上传）→ `cover.png`（`coverMode` 为 `template` 时，复用模板封面渲染）→ 平台默认取视频首帧。
- `meta.video` 存在即视为视频笔记；此时 `media` 保持为空（视频笔记只有一个视频）。图文页的「未配对视频」（`looseVideos`）要排除 `meta.video.file`，避免显示成孤儿视频。

**上传大文件**：现有上传接口是 JSON base64（`readBody` 上限 80MB，视频不够用，base64 也不划算）。新增二进制上传接口：

- `POST /api/notes/upload-file?account=<id>&noteId=<id>&filename=<名>`，请求体 `application/octet-stream`，按 chunk 流式写盘（零依赖即可），上限 1GB。
- 复用 `saveUpload` 的扩展名白名单与文件名清洗逻辑（抽出可复用的 `cleanName()`）；视频扩展名 `.mp4/.mov`，图片走原有 JSON 接口不变。
- 前端用 `XMLHttpRequest`（`fetch` 拿不到上传进度）。

**服务端**（`content.mjs` + `server.mjs`）：
- `setNoteVideo(acc, id, { file?, cover? })`：设置 / 更换视频与封面，校验文件在 `images/` 里存在；`noteDetail` 返回 `video` 及其访问路径；删除视频或封面 → 回收站，`meta.video` 相应清空。
- `noteBundle`：视频笔记打包为 `01-封面.png`（如有）+ `02-视频.<ext>` + `文案.txt`。

**前端**（`media.js`）：
- 配图区顶部加「图文 / 视频」切换（`meta.video` 存在默认视频）。切到视频时隐藏图片网格，显示：上传视频（显示进度条）、`<video>` 预览（浏览器解不了的格式如 HEVC 显示占位提示，同 HEIC 的处理）、封面三选一（不设置 / 截取当前帧（canvas 截图 → 走图片上传接口）/ 上传图片）。
- 切回图文时若已设视频，提示确认（视频保留在 images/，随时可切回）。

**发布手册**（`playbooks/publish.md`）增加「视频笔记」一节：打开发布页 → 「上传视频」标签 → 上传 `meta.video.file` → 封面按上面的优先级处理（有封面文件就上传；没有就保持页面默认首帧）→ 标题、正文、话题、可见范围同图文。异常规则（登录核对、风控停止、绝不重复发布）与图文一致。

## 2. 对标追踪（爆款雷达）

**现状**：对标拆解是一次性的；拆完不会知道对标又发了什么。

**数据设计**（对既有结构的增量，向后兼容）：
- `benchmarks/index.json` 条目新增：`tracking`（bool）、`lastCheckedAt`（上次追踪检查完成时间）、`newCount`（上次检查新发现的笔记数，用户查看后清零）、`radarNote`（可选，一句「哪篇可能爆了」的摘要）。
- `benchmarks/<id>/notes.json` 每条新增：`firstSeenAt`（首次采集时间）。**追踪检查按 `url` 去重，只追加新条目**（已有条目可更新互动数据，不改标题等）；旧数据没有 `firstSeenAt` 视为「早已存在」，不算新。
- `automation.json` 新增 `radar: { everyHours: 0, likesThreshold: 1000 }`（0 = 关闭；账号级设置）。

**职责划分（关键取舍）**：谁判断「爆了」？
- 候选 A：服务端解析 likes 字符串（"1.2万"）算阈值——要兼容「万 / w / 999+」等脏数据，边缘情况多。
- **选 B：判断交给 agent**。手册要求 agent 在追踪检查时：统计新笔记数写 `newCount`；若某篇新笔记的点赞超过 `radar.likesThreshold`，把「标题 + 点赞数 + 链接」写进 `radarNote`。服务端只负责把 `newCount / radarNote` 变成提醒，不解析数字。

**调度**（`automation.mjs`）：
- `PROMPTS.radar`：「检查追踪中的对标账号有没有新笔记，按 playbooks/benchmark.md 的『追踪检查』执行」。
- `#tickAccount` 增加第 4 类任务：`radar.everyHours > 0` 且该账号存在 `tracking` 的对标，且距 `lastRuns.radar` 超过间隔 → 派任务；`needsAwake()` 同步纳入该条件（防休眠「自动」档覆盖雷达）。

**提醒**（`alerts()`）：`newCount > 0` 或有 `radarNote` 时出一条 `kind: 'radar'` 提醒：「对标 @X 新增 N 篇笔记」+ `radarNote` 摘要；点击跳对标详情页（`onAlert` 增加路由）。用户点开详情 → 前端调 `POST /api/benchmarks/seen?id=` 清零 `newCount / radarNote`。

**前端**（`benchmark.js`）：
- 卡片：追踪开关（开时提示「agent 会按设置的间隔检查该账号的新笔记」）、`newCount` 角标、`radarNote` 摘要行。
- 详情页：`firstSeenAt` 在最近一次检查中出现的条目标「新」。
- 对标页顶部「追踪设置」（检查间隔、点赞阈值），读写 `POST /api/automation` 的 `radar`。

**手册**（`playbooks/benchmark.md`）增加「追踪检查」一节：遍历 `tracking` 的账号 → 慢速抓主页最新一屏笔记 → 按 url 去重追加（写 `firstSeenAt`）→ 算 `newCount`、按阈值写 `radarNote` → 更新 `lastCheckedAt`。没有浏览器能力时如实说明并停止，不要编造。

## 3. 历史笔记导入

**现状**：工作台从零开始，用户账号里已有的笔记和数据进不来，数据复盘对老账号没有历史可看。

**设计**：不加新数据结构，导入 = 往 `analytics/notes.json` 补条目。
- 手册 `playbooks/analytics.md` 增加「首次导入历史笔记」：从创作者中心「笔记管理」逐页慢速读取，为每篇笔记追加条目（按 `url` 跳过已有的）：`id`（a_）、`title`、`url`、`publishedAt`、`metrics` 当前累计值、`history` 一条当天快照、`imported: true`。导入的笔记只有单次快照，趋势图没有历史曲线是正常现象，手册里说明。
- 触发：数据复盘页加「导入历史笔记」按钮 → 走对话通道发任务给 agent（复用模块现有的发 prompt 机制）。没有浏览器能力时，agent 引导用户上传创作者中心导出表到 `imports/`（机制已有）。
- 不做 CSV 解析器：agent 能直接读 `imports/` 里的表格，维护一个列映射解析器不划算。

## 4. 新手引导

**设计**：检查清单式引导（非强制向导），纯前端实现，不新增服务端接口。
- `web/modules/onboarding.js`：首次打开（localStorage 无 `xhs-onboarded`）自动弹出浮层；概览页放「新手引导」入口可随时再看。
- 每步**自动检测状态打 ✓**，完成即勾亮，下一步给两个动作：「自己去」（跳对应面板）和「让 agent 帮忙」（复用概览页 quick-card 的发 prompt 机制）：

| 步骤 | 完成条件（检测） | 让 agent 帮忙 |
|---|---|---|
| 1. 连接 agent | `S.bridge` 正常 | — （黄/红时引导去设置页重跑自检） |
| 2. 账号定位 | `currentAccount().positioning` 非空 | 帮我梳理账号定位 |
| 3. 沉淀知识库 | 知识库文档数 > 初始模板数 | 帮我建立知识库基础文档 |
| 4. 找对标并拆解 | 对标数 ≥ 1 | 帮我找 3 个对标账号 |
| 5. 第一篇笔记 | 笔记数 ≥ 1 | 从我的定位出第一篇选题并写成笔记 |
| 6. 安排发布 | 有排期或已发布笔记 | — （跳发布排期页） |

- 完成全部或点「跳过引导」→ 写 localStorage `xhs-onboarded=1`，浮层不再自动弹出。
- 顺带解决新用户「打开 9 个面板不知道先点哪」的问题；概览页已有的 quick-card 与流水线保持不变，引导是它们的串联层。
