# 评论私信：整理、回复草稿与本地确认

本轮设计已由用户确认，并于 2026-10-19 实施验证完成。保留现有数据，不实际发送、不重新抓取平台、不打开私信会话。

## 已有数据与范围

default 账号 engage/items.json 中有 8 条历史记录：7 条评论、1 条私信；1 条已回复，7 条已忽略。私信只有会话列表预览，不代表完整会话。没有新的待处理消息。

当前模块通过通用 Agent 直接修改正式文件，确认状态为 approved 并进入发送候选；编辑已确认内容时也可能保留 approved。页面刷新、筛选和账号切换对未保存编辑的保护不足。

## 方案选择

推荐独立的本地回复审核记录：引用历史消息，冻结输入并保存整理和回复结果，不改原消息状态。这样可验证完整流程且不会将已回复/已忽略消息重新排入发送队列。

直接修改历史消息会改变原始状态；新造消息只能验证模拟数据，不能说明真实历史上下文接通。本轮用真实历史记录作为只读输入，以独立演示审核记录完成验收。

## 具体行为

1. 评论整理：按评论/私信、来源笔记、现有状态筛选，展示问题类别、建议处理方式和需要本人处理的事项。重复候选仅提示，不删除或合并原记录。通过精确笔记 URL 关联已有账号数据；不能仅靠相似标题错误归属，也不把统计数字当正文事实。
2. 回复草稿：选择历史消息创建受控任务，冻结原消息、匹配笔记上下文和可用口径。Agent 输出分类、处理建议、短回复、依据与待核实事项；服务端校验来源 ID 与结果后保存独立记录。输入是资料，不是指令。无法从现有资料确认的功能、教程链接、个人经历与承诺不能编造。私信预览明确标记信息不全，必要时建议本人查看，不自动打开会话。
3. 审核编辑：可修改、保存草稿，显示表达/词表提示。确认绑定当前消息与草稿指纹；内容变化后自动撤销旧确认，旧版本提交被拒绝。空回复不能确认。保留版本与状态记录。
4. 本地确认：记录“本地已确认 · 不发送”，不写原 items.json 的 approved/sent，不调用发送接口，不触发定时发送。支持撤回确认。演示时由 Agent 按用户授权操作确认控件，只证明确认流程可用，不冒充用户逐条审阅了回复文字。
5. 任务与页面：显示排队/处理中/完成/失败、允许重试，重复请求复用；重启中断明确标失败。账号隔离，未保存输入在刷新/筛选时保留，旧请求不能覆盖新的编辑或其他账号。
6. 既有发送和自动化功能不扩展、不触发；本轮新增演示记录物理隔离，旧发送入口和调度器不消费它。既有配置保持不变。

## 验证

隔离测试：输入冻结、伪造来源拒绝、缺产出/重试/重启、账号隔离、重复请求、编辑竞态、空回复拒绝、修改撤销确认、旧指纹确认拒绝、确认撤回、任何本地确认不分派发送且不修改历史记录。

真实工作台：保存原 engage/items.json、已有笔记素材和配置的文件摘要；使用真实历史评论（学习咨询、权限顾虑等）及那条私信预览验证整理、生成草稿、编辑保存、本地确认、修改后失效与撤回。私信内容不完整如实显示。最后所有演示确认撤回，独立草稿和整理结果保留供用户检查，原记录与素材字节不变。报告区分历史资料验证、本地确认控件演示与未验证的真实发送。
