# 小红书运营工作台（xhs-workbench）

你是这个技能包的执行者。用户通常**不懂技术**，环境准备、启动服务、排查问题都由你完成，只在必须由本人操作时（如安装软件需要输入电脑密码、登录小红书、扫码）才请用户动手，并用简单的话说明怎么做。

下文中 `<SKILL_DIR>` 指本文件所在目录；`WB` 指命令 `node "<SKILL_DIR>/scripts/workbench.mjs"`。数据默认存放在 `~/XHS-Workbench/`（可用环境变量 `XHS_WORKSPACE` 修改）。

## 一、用户说"打开工作台"时

按顺序执行，已完成的步骤会自动跳过：

1. **检查 Node.js**：运行 `node -v`，需要 18 或更高版本。
   - 没有安装或版本过低：见「附录 A」，装好后**新开一个终端**再继续（PATH 才会刷新）。这一步通过前，下面的命令都跑不了。
2. **环境自检**：`WB doctor`
   - 它只检查、不修改任何东西，输出每项 ✔/△/✖，缺的项下面直接给出 `FIX:` 命令。最后一行是 `RESULT: ok`、`RESULT: action-needed <项>` 或 `RESULT: blocked <项>`。
   - `blocked`：必须先解决（Node 过旧、数据目录不可写），按 `FIX` 处理后重跑 `WB doctor`。
   - `action-needed`：不影响启动，但会让部分功能不可用。**先用一句话告诉用户缺了什么、会少哪些功能、要装多大的东西，征得同意再执行 `FIX` 命令**（例如 ffmpeg 只影响参考视频与视频创作，图文笔记完全不受影响，用户可以先不装）。
   - 需要管理员权限、输入电脑密码、或点安装向导的步骤，请用户本人操作，你不要代劳。
   - 下载安装包前，先说清楚来源网址和大概体积；下载很慢时告诉用户“还在下载”，不要反复重试或换来源。
   - 装完后再跑一次 `WB doctor` 确认 ✔，不要凭安装命令没报错就当成功。
   - 想要机器可读的结果：`WB doctor --json`。
3. **初始化**：`WB setup`
   - 输出中显示「连接配置：尚未配置」时，执行第二节「连接自检」（注意：本机有多个 agent 时必须问用户，不要替用户选）。
4. **启动**：`WB start --open`
   - 会自动打开浏览器。把输出里的 `URL:` 链接也发给用户，方便收藏。
   - 浏览器没打开时，请用户手动打开该链接；如果你有浏览器控制能力，也可以自己打开。
5. 告诉用户：工作台已打开，可以在网页右侧的对话框里直接下达任务。
6. 如果连接模式是**收件箱模式**（`WB status` 可查看），接着进入第三节「值守模式」。

## 二、连接自检（首次使用 / 用户说"运行连接自检" / 工作台显示未连接）

目的：让网页里的消息能交给 agent 处理。有两种模式：

| 模式 | 工作方式 | 适用 |
|---|---|---|
| CLI 模式（优先） | 工作台直接调用 agent 的命令行（如 `claude -p`、`codex exec`） | 本机装有支持无界面运行的 agent 命令行 |
| 收件箱模式（兜底） | 消息进入队列，由你在当前会话中轮询领取、处理、回写 | 其他所有 agent（WorkBuddy、IDE 类 agent 等） |

执行：

```
WB bridge-test --agent <你自己的 id>
```

- `<你自己的 id>`：
  - 命令行类（CLI 模式）：`claude-code`、`codex`、`codebuddy`、`gemini`、`qwen`、`opencode`。
  - 桌面 / IDE 类（收件箱模式，没有命令行）：`workbuddy`、`cursor`、`trae`。
  - 你是其中之一，就必须带上自己的 id，这样网页里的对话才由你处理。不在列表里的 agent，用 `WB bridge-test --inbox`。
- **不要靠猜**：不带 `--agent` 运行时，如果本机同时有多个可用的 agent（例如装了 Claude Code，同时用户在 WorkBuddy 里和你对话），命令不会替用户决定，只会输出 `RESULT: choose <id 列表>`，且不保存任何配置。此时**问用户**想让网页里的对话由哪一个处理（说明：CLI 模式不用保持窗口；收件箱模式需要对应 agent 的窗口一直开着），再带上 `--agent <id>` 重跑。
- 已经配置过的连接，不带参数重跑会沿用原选择，不会被别的 agent 悄悄改掉。用户想换，在网页「连接与设置」里选，或重新带 `--agent` 运行。
- 每个候选最长测试约 3 分钟。输出最后一行是 `RESULT: cli <id>`、`RESULT: inbox [<id>]` 或 `RESULT: choose ...`。
- 你指定的命令行 agent 没通过测试时，不会偷偷换成别的 agent，而是设为收件箱模式并告诉你原因；修复后用同样的 `--agent` 重跑。
- 想让旧的“自动挑第一个能用的”行为：加 `--auto`（只在无人值守的批量安装时用）。
- 测试失败时，读一下 `adapters/` 下对应的说明文件排查（常见原因：命令行没登录、权限参数不支持、版本太旧）。
- 想接入列表以外的 agent 命令行：见 `adapters/generic.md`。

自检完成后，向用户简单说明结果（例如：「已连接 Claude Code，之后你在网页里发的消息都会由它处理」）。

## 三、值守模式（收件箱模式专用）

用户说"进入值守模式"，或连接模式为收件箱模式时，在当前会话中循环执行：

1. 领取任务：`WB inbox-next --wait 110`
   - 输出 `NO_TASK`：没有新消息，直接再次执行第 1 步。
   - 持续值守，不要因为长时间没有消息就自行停止。只有用户明确说“停止值守”、或你的会话/工具调用被系统中断时才结束；若被迫结束，网页会显示“agent 离线”，用户回来说一句“进入值守模式”即可恢复。
2. 输出 `TASK_ID: xxx` 和任务内容：任务内容就是用户在网页里发的消息（已附带账号和环境信息）。像处理用户直接对你说的话一样完成它。
3. 处理时间较长时，可以先回写进度（不结束任务）：
   ```
   WB inbox-reply <TASK_ID> <<'EOF'
   正在拆解对标账号，已完成 3/10 篇……
   EOF
   ```
4. 完成后回写最终回复并结束任务（正文为 Markdown，会显示在网页对话框中）：
   ```
   WB inbox-reply <TASK_ID> --final <<'EOF'
   这里是给用户的回复
   EOF
   ```
   - Windows PowerShell 等不支持 `<<'EOF'` 时：先把回复写进临时文件，再用 `--file <路径>` 传入。
   - 任务无法完成：`WB inbox-reply <TASK_ID> --error "原因"`
5. 回到第 1 步。

值守期间用户在 agent 窗口里直接对你说话时，优先回应用户。

## 三点五、浏览器控制（自动发布 / 抓评论 / 抓数据）

M3 的自动发布、检查评论私信、抓取数据都需要 agent 能操作浏览器。用户想用这些自动功能时：

- **收件箱模式**：你在自己的会话里用自带的浏览器 / 电脑控制能力完成即可。
- **多账号**：Playwright 方式下每个账号有独立的浏览器资料，各自登录一次即可；任何网页操作前都按 `playbooks/browser.md` 核对登录的小红书号。
- **CLI 模式（Claude Code）**：运行 `WB browser-setup`，按输出向用户说明会做什么修改，用户同意后运行 `WB browser-setup --yes`（或 `--engine chrome --yes` 使用用户日常的 Chrome）。详见 `adapters/claude-code.md`。
- 用户不想开放浏览器控制：工作台的「到点提醒 + 手动发布助手」、截图导入等方式依然可用。

定时任务（定时发布、定时检查评论、每日抓数据）由工作台服务触发，**电脑需要开机且工作台保持运行**（`WB status` 查看）。

## 四、处理工作台任务的通用规则

- 网页发来的任务开头带有【小红书运营工作台】标记，里面有当前账号、数据目录等信息。
- 做某个模块的事情之前，先读 `<SKILL_DIR>/playbooks/` 下对应的手册（索引：`playbooks/README.md`）。
- 产出物写成文件存进数据目录，工作台会自动显示；回复里写明文件路径。
- 不删除任何文件，需要删除时移到数据目录的 `.trash/`。
- 登录、验证码、支付等账号安全相关操作，一律请用户本人完成。
- 控制浏览器或电脑操作小红书时，遵守 `playbooks/README.md` 中的「账号安全规则」。

## 五、常用命令

| 命令 | 作用 |
|---|---|
| `WB doctor [--json]` | 环境自检：缺什么、怎么装（只检查不修改） |
| `WB upgrade --check` | 查看当前版本、数据版本与最近一次升级 |
| `WB upgrade --package <zip> [--yes]` | 用新版安装包升级（见下方“升级”）；不带 `--yes` 只预检 |
| `WB status` | 查看工作台和连接状态 |
| `WB open` | 重新在浏览器中打开工作台 |
| `WB stop` | 停止工作台（用户说"关闭小红书工作台"时执行） |
| `WB start --open` | 启动（已运行时直接打开） |
| `WB lint --account <账号id> --note <笔记id>` | 检查笔记字数与违禁词 |
| `WB browser-setup [--engine chrome] [--yes]` | 为 CLI 模式的 agent 开启浏览器控制（Playwright 方式下每个账号一份独立浏览器） |
| `WB autostart on\|off\|status` | 开机自启（用户说"开机自动运行工作台"时执行，先征得同意） |
| `WB backup` / `WB restore <备份> --yes` | 备份数据 / 从备份恢复（恢复前先征得同意） |
| `WB kb-search "<问题>"` | 按相关度检索知识库 |

运行日志：`~/XHS-Workbench/logs/server.log`。

## 升级（用户说"升级工作台"/给了新版安装包时）

1. 预检：`WB upgrade --package <zip路径>`。它只检查安装包（结构完整、版本号、路径安全），输出当前版本 → 新版本和 SHA-256，最后一行 `RESULT: confirm`（可以升级）或 `RESULT: refused`（同版本/更旧版本/旧副本已存在，原因写在输出里）。
2. 把“当前 vX → 新版 vY、会先备份数据、旧版本留作回退副本”告诉用户，**征得同意**。安装包来源不明时不要升级；用户给了校验值就和输出的 SHA-256 核对。
3. 执行：`WB upgrade --package <zip路径> --yes`。它会停止工作台、先备份全部用户数据（`upgrade-pre-*.zip`）、把现有技能包改名为 `xhs-workbench.bak-<旧版本>`、换上新版本，并重新启动（原本在运行时）。新版本启动时会再做一次升级前备份并执行数据迁移。
4. 升级后核对：`WB upgrade --check` 的“最近一次变更”应显示 ok；`WB doctor` 无 ✖。迁移失败时网页「连接与设置」会显示原因，数据不会被推进到半成品状态，备份名同时给出；这时不要反复重试，把原因告诉用户。
5. 想回退：停止工作台，删掉当前 `xhs-workbench`，把 `xhs-workbench.bak-<版本>` 改回 `xhs-workbench`。如果新版本已经迁移过数据，再从 `upgrade-*` 备份恢复（`WB restore <备份名> --yes`，先征得用户同意）。
6. 提示“移走旧版本失败（EBUSY/EPERM）”时：关闭占用技能包目录的终端/编辑器，确认工作台已停止后重试；旧版本此时没有被改动。
7. 只替换了文件夹（没用 `upgrade`）也安全：启动时服务会自动备份并迁移。若提示“数据来自更新的版本”，说明装的是更旧的版本，换回新版本的技能包，不要强行启动。

## 附录 A：安装 Node.js 和 ffmpeg

`WB doctor` 会按本机的包管理器给出现成命令，下面是它的依据，供你处理例外情况。

**Node.js ≥ 18（必需）**

- **macOS**：有 Homebrew（`brew -v` 能运行）就 `brew install node`；否则请用户到 https://nodejs.org 下载 LTS 版 .pkg 安装包，双击安装（需要输入电脑密码，请用户本人操作）。
- **Windows**：`winget install OpenJS.NodeJS.LTS`；没有 winget 就请用户到 https://nodejs.org 下载 LTS 版 .msi 安装（可能需要管理员权限）。装完必须新开终端。
- **Linux**：用系统包管理器，或使用 nvm。

**ffmpeg（推荐；参考视频、视频创作需要，图文笔记不需要）**

- **macOS**：`brew install ffmpeg`；没有 Homebrew 时先请用户安装 Homebrew（https://brew.sh）。
- **Windows**：优先 `winget install Gyan.FFmpeg`，其次 `choco install ffmpeg -y` 或 `scoop install ffmpeg`。三者都没有时：从 https://www.gyan.dev/ffmpeg/builds/ 下载 `ffmpeg-release-essentials.zip`（约 110MB，网络差时可能要十几分钟），解压到 `%USERPROFILE%\ffmpeg`。工作台会在这个目录下自动查找，不改 PATH 也能用；改了 PATH 的话需要新开终端。
- 装完用 `WB doctor` 确认 ffmpeg 和 ffprobe 都是 ✔。

两台电脑的差异：实况图（Live Photo）制作、本地二维码、截图 OCR 核对目前只支持 macOS；Windows 上这些功能会明确提示不可用，其余功能完全相同。

## 附录 B：常见问题

- **网页提示「令牌无效」**：执行 `WB open`，用新链接打开。
- **网页提示「未连接 agent」**：执行第二节「连接自检」。
- **CLI 模式下回复报错「权限」相关**：agent 在无界面模式下无法弹出授权确认，需要在 `~/XHS-Workbench/config/bridge.json` 的 `adapter.args` 中加入对应 agent 的自动授权参数，详见 `adapters/` 下的说明。修改前先向用户说明这会让 agent 无需确认即可修改文件。
- **端口被占用**：工作台会自动在 17890–17910 之间找可用端口。
