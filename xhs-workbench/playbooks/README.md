## 公司口径与本地笔记

| | 中枢知识库（`search_knowledge`） | 本地 `knowledge/` |
|---|---|---|
| 放什么 | **公司口径**：品牌调性与人设、产品卖点、违禁词与广告法、爆款规律、售后话术 | **本账号的笔记**：账号定位、对标拆解、复盘结论、账号经验、素材库 |
| 谁说了算 | 以它为准（主管维护、审核；每次检索有审计） | 只对本账号有效 |
| 谁能改 | 只能用 `propose_improvement` 提建议，主管审核后生效 | agent 可以直接写 |

- 两边冲突以中枢为准，并告诉用户有出入；没接中枢时只用本地笔记。
- 不要把公司口径类内容写进本地当标准；以前遗留的 `品牌口径/`、`爆款方法论/` 目录只读参考。
- 热点、平台趋势这类公司资料里没有的外部信息可以联网查；公司自己的事以中枢为准，不要用联网搜索代替。

## 与中枢技能的分工

接入企业中枢后，agent 同时有两套指引，**分工不同，不要混用**：

| | 中枢技能（`read_skill`） | 本目录的操作手册 |
|---|---|---|
| 管什么 | **业务标准**：口吻、选题标准、合规红线、评论回复原则、复盘指标 | **怎么在工作台里做**：文件位置和格式、检查点、受控任务的输入输出、浏览器与账号安全 |
| 谁维护 | 公司主管 / 老板（在中枢控制台里改） | 工作台开发（随工作台版本发布） |

- 各手册开头有一行「中枢技能」，写明对应的公司技能；做这件事前先读，**同一会话读过就不用重复读**。
- **优先级**：文件格式、存放位置、检查点、浏览器与账号安全、不自动发布 → **以本目录手册为准**；口吻、选题标准、合规红线、回复原则、复盘指标 → **以中枢技能为准**。
- **两者直接冲突时，先停下来说明，不要自己挑一个**，并对中枢技能提改进建议（`propose_improvement`）。
- 读不到中枢技能（没接中枢、没有权限、读取失败、没有这类工具）时，直接按本手册做，**不要重试，也不要因此中断**。
- 读了公司技能或知识库后，发现内容有错误、过时或缺步骤，用 `propose_improvement` 提交改进建议——只是建议，不要自己改；有把握才提，不是每次都提。本手册自身的问题（格式、流程）不走这条路，直接告诉用户。

## 自动任务

提示词以【自动任务 · …】开头的消息来自工作台的定时调度（定时发布、定时检查评论、定时抓数据、对标追踪检查），此时用户可能不在电脑前：
- 按对应手册执行，结果务必写回文件（工作台靠文件判断任务结果）。
- 需要用户介入（登录、验证码、风控提示）时，停止并写明原因，不要等待太久。

## 数据目录结构

```
~/XHS-Workbench/
├── config/            accounts.json（账号）、bridge.json（连接）、settings.json
├── accounts/<账号id>/
│   ├── benchmarks/    对标账号（index.json + checkpoints/ 逐条检查点 + <对标id>/snapshot.json、头像、report.md / notes.json / screenshots/）
│   ├── topics/        选题池 topics.json
│   ├── notes/         笔记，每篇一个目录（meta.json + content.md + images/ + cover.png）
│   ├── schedule.json  发布排期
│   ├── engage/        评论私信 items.json
│   ├── analytics/     数据（notes.json、account.json、reports/、imports/）
│   └── automation.json  自动化设置（定时检查、频率限制等，由工作台维护）
├── knowledge/         本地知识库：本账号的笔记（Markdown；公司口径在中枢知识库）
├── chats/             网页对话记录
├── logs/              运行日志
└── .trash/            回收站
```

## JSON 文件写入约定

- 修改 JSON 时先读取原文件，只改需要的字段，保留其他字段，写回合法 JSON。对标观察例外：按 `benchmark.md` 写各阶段独立检查点，由服务校验并合并 `snapshot.json`，不要直接覆盖观察文件。
- 直接用读写文件的工具编辑，不要为此专门写脚本（无界面模式下执行命令可能被禁止）。
- 不要删除条目和文件；用户在界面上删除时会自动移入回收站。

## 账号安全规则（控制浏览器 / 电脑操作小红书时必须遵守）

1. 登录、扫码、验证码、短信验证一律由用户本人完成，你不接触密码。
2. 使用用户自己已登录的浏览器，不新建账号、不批量切换账号。
3. 模拟真人节奏：每个操作之间随机停顿几秒，不要短时间内大量发布、点赞、评论、关注。
4. 评论和私信回复默认先生成草稿给用户确认，用户明确允许后才自动发送。
5. 出现验证码、"操作频繁"、风险提示、异常弹窗时，立即停止并告诉用户。
6. 发布前确认内容不含违禁词、虚假宣传、未授权的他人图片。
