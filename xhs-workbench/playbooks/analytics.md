# 数据复盘操作手册

目标：定期记录数据，找出"什么有效、什么无效"，把结论写回知识库，指导下一轮选题和创作。

## 数据位置

当前账号数据目录下 `analytics/`：

```
analytics/
├── notes.json      每篇笔记的最新数据 + 历史快照
├── account.json    账号级每日数据
├── reports/        复盘报告（Markdown）
└── imports/        用户上传的导出表格 / 截图（只读）
```

### notes.json

```json
{
  "updatedAt": "2026-10-15T09:00:00.000Z",
  "items": [
    {
      "id": "a_xxx",
      "noteId": "n_xxx",
      "title": "笔记标题",
      "url": "笔记链接",
      "publishedAt": "2026-10-10",
      "metrics": { "views": 12000, "likes": 830, "collects": 560, "comments": 42, "shares": 18, "follows": 25 },
      "history": [
        { "date": "2026-10-14", "views": 9800, "likes": 700, "collects": 480, "comments": 35, "shares": 15, "follows": 20 },
        { "date": "2026-10-15", "views": 12000, "likes": 830, "collects": 560, "comments": 42, "shares": 18, "follows": 25 }
      ]
    }
  ]
}
```

- `metrics` 是最新累计值；`history` 每天最多一条（同一天重复抓取就覆盖当天那条），日期格式 `YYYY-MM-DD`。
- 数字尽量写成数值；页面显示"1.2万"时可以原样写字符串，工作台能识别。
- `noteId`：如果能和工作台里的笔记对应上（看 `notes/*/meta.json` 的 `publishedUrl` 或标题），就填上。
- 新笔记追加条目，`id` 用 `a_` + 任意字母数字；不要删除旧笔记。

### account.json

```json
{ "history": [ { "date": "2026-10-15", "followers": 5230, "views": 45000, "likes": 3100, "collects": 2200, "comments": 180 } ] }
```

每天一条，同一天覆盖。字段拿不到就省略。

- `followers` 是当天的**粉丝总数**；`views`、`likes`、`collects`、`comments`、`follows` 是**当天新增**（创作者中心「账号概览」按日给出的数字）。
- 工作台的「每日趋势」图直接画这些值。

## 抓取数据

1. 用浏览器控制工具打开创作者中心的数据中心 / 笔记管理页面（未登录时请用户登录，规则同 `publish.md`）。只读取，不做任何修改操作。
2. 读取近 30 天发布的笔记数据和账号总览数据，更新 `notes.json`、`account.json`。
3. 没有浏览器能力时：读取 `imports/` 里用户上传的导出表格（CSV / Excel）或截图来整理；都没有就告诉用户如何从创作者中心导出数据并上传。
4. 拿不到的数据留空，不要估算或编造。
5. 回复用户：更新了多少篇、数据最好和最差的笔记各是什么。

## 写复盘报告

保存到 `reports/YYYY-MM-DD-<主题>.md`，例如 `2026-10-15-周复盘.md`：

```markdown
# 周复盘：10/09 - 10/15

## 数据概览
本周发布 N 篇，阅读 / 点赞 / 收藏 / 涨粉，与上周对比

## 表现最好的笔记
| 笔记 | 阅读 | 互动率 | 为什么好 |

## 表现不佳的笔记
| 笔记 | 阅读 | 互动率 | 可能的问题 |

## 结论
- 继续做：
- 停止做：
- 尝试做：

## 下周行动
1. 具体、可执行……
```

- 互动率 = (点赞 + 收藏 + 评论) / 阅读。
- 分析要结合选题（`topics/`）、标题、封面（`notes/`）和发布时间，不只看数字。
- 写完后按 `knowledge.md` 把"继续做 / 停止做"的结论沉淀到知识库 `复盘结论/`，已有相近结论就补充或修正。
