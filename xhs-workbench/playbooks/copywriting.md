# 文案操作手册

> **中枢技能**：xhs-writing、xhs-compliance（标题与正文撰写、违禁词与广告法自查）——公司统一的业务标准，做这件事之前先用 `read_skill` 读；读不到（没接中枢、没权限、失败）就只按本手册做，不要重试。优先级见 `README.md`「与中枢技能的分工」。

## 数据位置

当前账号数据目录下 `notes/<笔记id>/`：

```
notes/<笔记id>/
├── meta.json      标题、话题、状态、封面规格
├── content.md     正文（纯文本，可含 emoji，不要用 Markdown 标题/加粗语法）
├── images/        配图和实况图的动态视频（.mov / .mp4）
└── cover.png      封面（由工作台根据 meta.json 的 cover 自动生成）
```

### meta.json

```json
{
  "id": "n_xxx",
  "title": "正式标题（≤20 字）",
  "titleOptions": ["备选标题1", "备选标题2"],
  "tags": ["话题1", "话题2"],
  "topicId": "t_xxx",
  "status": "draft | ready | published",
  "visibility": "public | private（仅自己可见，默认 public）",
  "coverMode": "template | first（template：用 cover.png 模板封面；first：用第一张配图当封面）",
  "media": [
    { "file": "IMG_1234.HEIC", "video": "IMG_1234.MOV" },
    { "file": "step2.jpg" }
  ],
  "cover": { "...": "封面规格，见 cover.md" },
  "coverOptions": [],
  "createdAt": "…",
  "updatedAt": "…"
}
```

- 修改 meta.json 时保留其他字段，只改需要的；更新 `updatedAt`。
- 新建笔记：`id` 用 `n_` + 任意字母数字，建好目录和两个文件，`status` 为 `draft`。
- `tags` 不带 `#`。
- `media` 是配图的发布顺序：每项一张静态图（`file`），带 `video` 的是**实况图**（静态图 + 同一时刻的动态视频）。用户通常在工作台里排序和配对，你一般不用改；需要改时只填 `images/` 里实际存在的文件名。
- 图片总数（模板封面 + 配图）不超过 18 张。

## 写作步骤

1. **先查口径**：公司口径用中枢工具查（`search_knowledge`：《品牌调性与人设》人设与语气、《产品资料库》卖点、《违禁词与广告法》禁用说法、《历史爆款笔记》爆款规律）；本账号笔记看本地 `账号定位/`、`素材库/` 和相关的 `对标拆解/`。公司口径与本地笔记不一致时以中枢为准；没接中枢时只看本地笔记。
2. **定标题**：给 5 个备选写进 `titleOptions`，挑最好的一个作为 `title`。
   - ≤20 字；关键词和钩子放前面；常用套路：数字清单、痛点提问、反常识、结果前置、身份代入。
3. **写正文**（content.md）：
   - 开头 1-3 行：直接给出"这篇能帮你什么"或戳中痛点。
   - 主体：分段短句，每段 1-3 行；用 emoji 或序号做视觉分隔；给具体步骤、数字、例子。
   - 结尾：一句总结 + 自然的互动引导（提问 / 收藏提示），避免"求赞求关注"。
   - 全文 ≤1000 字，一般 300-600 字效果最好。
4. **话题**：5-8 个，大词 + 精准长尾词搭配，和内容强相关。
5. **自检**（见下）后保存，回复用户：标题、正文摘要、自检结果。

## 发布前检查

逐项确认，有问题就改或在回复里提示：

- [ ] 标题 ≤20 字，正文 ≤1000 字
- [ ] 没有违禁 / 风险词。**最终以中枢《违禁词与广告法》为准**（接入中枢时先用 `search_knowledge` 对照）；本地快速自查词表只是常见词，见技能包 `web/lint.js`（绝对化用语、医疗功效、虚假承诺、站外引流、诱导互动）；也可运行 `node <技能包目录>/scripts/workbench.mjs lint --account <账号id> --note <笔记id>`
- [ ] 符合中枢《品牌调性与人设》和账号定位的语气
- [ ] 信息准确，数据和功效有依据
- [ ] 开头 3 行有吸引力，结尾有互动引导
- [ ] 话题标签相关、数量合适

## 改写

用户要求改写时，保留原意和关键信息，按要求调整；改动较大时在回复里说明改了什么。

## 工作台受控文案任务

当提示明确为「工作台受控文案任务」时，以该任务的冻结输入与结果 JSON 契约为准：只读取参考材料并写指定结果文件，不直接修改正式笔记。改写仅返回正文和标签，标题优化仅返回五个不同标题及理由，检查只返回报告。引用检查原文时使用笔记中的连续原文，不添加省略号或拼接。区分已采集观察、拆解结论与待核实事实，不伪造效果或个人经历。服务端校验结果后回填，保留原稿快照；不得发布。
