# 文案操作手册

## 数据位置

当前账号数据目录下 `notes/<笔记id>/`：

```
notes/<笔记id>/
├── meta.json      标题、话题、状态、封面规格
├── content.md     正文（纯文本，可含 emoji，不要用 Markdown 标题/加粗语法）
├── images/        配图
└── cover.png      封面（由工作台根据 meta.json 的 cover 自动生成）
```

### meta.json

```json
{
  "id": "n_xxx",
  "title": "正式标题（≤20 字）",
  "titleOptions": ["备选标题1", "备选标题2"],
  "tags": ["话题1", "话题2"],
  "topicId": "t_xxx",
  "status": "draft | ready | published",
  "visibility": "public | private（仅自己可见，默认 public）",
  "cover": { "...": "封面规格，见 cover.md" },
  "coverOptions": [],
  "createdAt": "…",
  "updatedAt": "…"
}
```

- 修改 meta.json 时保留其他字段，只改需要的；更新 `updatedAt`。
- 新建笔记：`id` 用 `n_` + 任意字母数字，建好目录和两个文件，`status` 为 `draft`。
- `tags` 不带 `#`。

## 写作步骤

1. **先查知识库**：`账号定位/`（人设与语气）、`品牌口径/`（卖点与禁用说法）、`爆款方法论/`、`素材库/`，以及相关的 `对标拆解/`。
2. **定标题**：给 5 个备选写进 `titleOptions`，挑最好的一个作为 `title`。
   - ≤20 字；关键词和钩子放前面；常用套路：数字清单、痛点提问、反常识、结果前置、身份代入。
3. **写正文**（content.md）：
   - 开头 1-3 行：直接给出"这篇能帮你什么"或戳中痛点。
   - 主体：分段短句，每段 1-3 行；用 emoji 或序号做视觉分隔；给具体步骤、数字、例子。
   - 结尾：一句总结 + 自然的互动引导（提问 / 收藏提示），避免"求赞求关注"。
   - 全文 ≤1000 字，一般 300-600 字效果最好。
4. **话题**：5-8 个，大词 + 精准长尾词搭配，和内容强相关。
5. **自检**（见下）后保存，回复用户：标题、正文摘要、自检结果。

## 发布前检查

逐项确认，有问题就改或在回复里提示：

- [ ] 标题 ≤20 字，正文 ≤1000 字
- [ ] 没有违禁 / 风险词。词表见技能包 `web/lint.js`（绝对化用语、医疗功效、虚假承诺、站外引流、诱导互动）；也可运行 `node <技能包目录>/scripts/workbench.mjs lint --account <账号id> --note <笔记id>`
- [ ] 符合知识库里的品牌口径和人设语气
- [ ] 信息准确，数据和功效有依据
- [ ] 开头 3 行有吸引力，结尾有互动引导
- [ ] 话题标签相关、数量合适

## 改写

用户要求改写时，保留原意和关键信息，按要求调整；改动较大时在回复里说明改了什么。
