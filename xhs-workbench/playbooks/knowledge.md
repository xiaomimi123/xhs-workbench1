# 知识库操作手册

知识库是整个工作台的"大脑"：品牌口径、爆款方法、对标拆解、复盘结论都沉淀在这里。写文案、做选题、回复评论前，先在知识库里查相关内容。

## 位置与结构

`~/XHS-Workbench/knowledge/`，所有账号共享。默认目录：

| 目录 | 放什么 |
|---|---|
| `账号定位/` | 每个账号的定位、人群、人设、内容支柱（一个账号一篇） |
| `品牌口径/` | 产品卖点、标准话术、禁用说法、评论回复口径 |
| `爆款方法论/` | 标题公式、封面规律、正文结构、平台规则 |
| `对标拆解/` | 对标账号拆解报告（一个账号一篇或一个子目录） |
| `复盘结论/` | 数据复盘得出的有效 / 无效经验 |
| `素材库/` | 金句、案例、可复用的段落 |

可以按需新增目录，目录名用中文、简短。

## 文档格式

每篇文档是一个 `.md` 文件，开头带 frontmatter：

```markdown
---
title: 标题公式合集
tags: [标题, 爆款]
account: acc_xxx        # 可选：只适用于某个账号时填写账号 id
source: 对标账号 @xxx 拆解  # 可选：来源
updated: 2026-10-15
---

# 标题公式合集

正文……
```

- 文件名用中文标题即可，例如 `爆款方法论/标题公式合集.md`。
- 一篇文档讲一件事；内容很长时拆成多篇。
- 结论要具体可执行（"标题前 8 个字出现数字的笔记点击率更高"），避免空话。
- 写明来源和日期，方便以后判断是否过时。

## 常见操作

- **查找**：用 grep 等工具在 `knowledge/` 下搜索关键词，读取相关文档后再回答。
- **新增**：先搜索是否已有相近文档，有则在原文档上补充，没有再新建。
- **更新**：修改内容并更新 `updated` 日期；推翻旧结论时保留一句说明（"2026-10 复盘后修正：……"）。
- **删除**：不要删除，移到 `~/XHS-Workbench/.trash/knowledge/`。
- **整理**：用户要求整理时，合并重复文档、补充缺失的 frontmatter、调整目录，完成后汇报改动清单。

## 知识库管家

工作台会按设置的间隔自动派【自动任务 · 知识库管家】。执行流程：

1. **盘一遍知识库**：列出每个目录下的文档和 `updated` 日期，对照数据目录里最近新增的内容（新的拆解报告、复盘报告、新笔记）。
2. **归档**：新拆解 / 复盘的结论还没有进知识库的，按 knowledge.md 的规则补写进去；不要整篇复制报告，提炼成可执行的结论并写明来源和日期。
3. **提炼素材库**：`materials/` 里有新收藏的素材（对照 index.json 的 `updatedAt`）时，读素材批注和文件本体，把可模仿的手法提炼进「爆款方法论/」（写明「来自素材库」）。素材本体不动。
4. **合并与修正**：发现内容重复或相近的文档，合并成一篇（保留信息多的一篇做主体）；结论被新数据推翻时，保留一句修正说明（「2026-10 复盘后修正：……」）。
5. **补全格式**：缺 frontmatter（title / tags / updated）的补上；`account` 字段标注适用的账号 id。
6. **维护索引**：更新 `知识库地图.md`——每个目录一行，列主题和最近更新时间，放在知识库根目录。没有这篇就创建。
7. **汇报**：回复用户改动了哪些文档（新增 / 合并 / 修正各几篇），以及知识库还缺什么。

原则：整理是**精炼和归位**，不是重写；原文档里有用的细节不要在整理时丢掉。

## 和其他模块的关系

- 对标拆解、数据复盘的结论 → 写入知识库
- 选题、文案、封面、评论回复 → 先读知识库再动手，回复中注明参考了哪些文档
