# 知识库操作手册

> **中枢技能**：无（知识库的分工本手册自己定义）。公司统一口径放在企业中枢的知识库里，本地知识库只放**本账号的笔记**。

## 两套知识库，各管各的

| | 中枢知识库 | 本地知识库（本手册讲的） |
|---|---|---|
| 位置 | 企业中枢，用中枢工具 `search_knowledge` 查 | `~/XHS-Workbench/knowledge/` |
| 放什么 | **公司口径**：品牌调性与人设、产品资料、违禁词与广告法、历史爆款笔记、售后 FAQ 等 | **本账号的笔记**：账号定位、对标拆解、复盘结论、账号经验、素材库 |
| 谁说了算 | 以它为准 | 只对本账号有效 |
| 谁能改 | 只能 `propose_improvement` 提建议，主管审核后生效 | agent 可以直接写 |

规则：

- 写文案、做选题、回复评论前：**先查中枢（公司口径），再看本地笔记（本账号情况）**。两边不一致以中枢为准，并告诉用户有出入。
- 没接中枢（没有中枢工具、没有权限、调用失败）时，只用本地笔记，不要重试。
- **不要把公司口径类内容（品牌口径、爆款方法论、违禁词）写进本地当标准。** 值得全公司共享的内容，经用户确认后用 `propose_improvement` 提给中枢，由主管审核。
- 以前遗留的 `品牌口径/`、`爆款方法论/` 目录：保留，当参考读；公司口径以中枢为准，不要再往里面新增、合并或改写。

## 位置与结构

`~/XHS-Workbench/knowledge/`，本机所有账号共用这个目录（用 `account` 字段区分适用的账号）。默认目录：

| 目录 | 放什么 |
|---|---|
| `账号定位/` | 每个账号的定位、人群、人设、内容支柱（一个账号一篇） |
| `对标拆解/` | 对标账号拆解报告（一个账号一篇或一个子目录） |
| `复盘结论/` | 数据复盘得出的有效 / 无效经验（只对本账号） |
| `账号经验/` | 只适用于本账号的做法和心得（从素材库提炼出来的手法也放这里，写明「来自素材库」） |
| `素材库/` | 金句、案例、可复用的段落 |

可以按需新增目录，目录名用中文、简短。

## 文档格式

每篇文档是一个 `.md` 文件，开头带 frontmatter：

```markdown
---
title: 标题公式合集
tags: [标题, 爆款]
account: acc_xxx        # 可选：只适用于某个账号时填写账号 id
source: 对标账号 @xxx 拆解  # 可选：来源
updated: 2026-10-15
---

# 标题公式合集

正文……
```

- 文件名用中文标题即可，例如 `账号经验/标题公式合集.md`。
- 一篇文档讲一件事；内容很长时拆成多篇。
- 结论要具体可执行（"标题前 8 个字出现数字的笔记点击率更高"），避免空话。
- 写明来源和日期，方便以后判断是否过时。

## 常见操作

- **查找**：先用中枢 `search_knowledge` 查公司口径；再用 grep 等工具在 `knowledge/` 下搜索本账号的笔记，读取相关文档后再回答。
- **新增**：先搜索是否已有相近文档，有则在原文档上补充，没有再新建。只写本账号的内容。
- **更新**：修改内容并更新 `updated` 日期；推翻旧结论时保留一句说明（"2026-10 复盘后修正：……"）。
- **删除**：不要删除，移到 `~/XHS-Workbench/.trash/knowledge/`。
- **整理**：用户要求整理时，合并重复文档、补充缺失的 frontmatter、调整目录，完成后汇报改动清单。
- **想共享给全公司**：先问用户；用户明确同意后用 `propose_improvement` 提交到中枢相应的知识库（`kind` 用 `doc` 或 `new_doc`），告诉用户建议编号，说明要主管审核后才生效。

## 知识库管家

工作台会按设置的间隔自动派【自动任务 · 知识库管家】。**只整理本账号的笔记**（`账号定位/`、`对标拆解/`、`复盘结论/`、`账号经验/`、`素材库/`），不碰公司口径类内容。执行流程：

1. **盘一遍知识库**：列出每个目录下的文档和 `updated` 日期，对照数据目录里最近新增的内容（新的拆解报告、复盘报告、新笔记）。
2. **归档**：新拆解 / 复盘的结论还没有进知识库的，按本手册的规则补写进去；不要整篇复制报告，提炼成可执行的结论并写明来源和日期。
3. **提炼素材库**：`materials/` 里有新收藏的素材（对照 index.json 的 `updatedAt`）时，读素材批注和文件本体，把可模仿的手法提炼进 `账号经验/`（写明「来自素材库」）。素材本体不动。
4. **合并与修正**：发现内容重复或相近的文档，合并成一篇（保留信息多的一篇做主体）；结论被新数据推翻时，保留一句修正说明。
5. **补全格式**：缺 frontmatter（title / tags / updated）的补上；`account` 字段标注适用的账号 id。
6. **维护索引**：更新 `知识库地图.md`——每个目录一行，列主题和最近更新时间，放在知识库根目录。没有这篇就创建。
7. **汇报**：回复用户改动了哪些文档（新增 / 合并 / 修正各几篇），以及知识库还缺什么；发现值得全公司共享的结论，**只在汇报里列出**，由用户决定要不要提交给中枢。

不要整理、合并、改写 `品牌口径/`、`爆款方法论/` 这类公司口径目录（遗留的，只读）。原则：整理是**精炼和归位**，不是重写；原文档里有用的细节不要在整理时丢掉。

## 和其他模块的关系

- 对标拆解、数据复盘的结论 → 写入本地知识库（本账号笔记）
- 选题、文案、封面、评论回复 → 先查中枢（公司口径），再读本地笔记（本账号情况），回复中注明参考了哪些文档
