# 浏览器与账号核对手册

所有需要操作小红书网页的任务（发布、检查评论私信、抓数据、登录）都**先**按本手册检查登录和账号，再执行各自的手册。

## 浏览器与封号风险（必须遵守）

- **一律有头运行**：无头浏览器的指纹特征（webdriver 标记、缺失的字体 / 插件 / 分辨率特征）是平台风控重点，**用无头模式抓取小红书有实实在在的封号风险**。browser-setup 默认有头，除非用户明确接受风险并要求。
- **优先系统真实浏览器**：browser-setup 会自动探测并优先使用系统安装的 Microsoft Edge / Google Chrome（真实浏览器二进制，但不能保证与真人环境一致或规避平台风控）。没有系统浏览器时才用 Playwright 内置浏览器。
- **独立资料目录**：工作台的浏览器资料（`browser-profiles/`）与用户日常浏览器完全隔离；登录资料可跨任务复用，但平台可能要求重新登录——**不要清空、重置这个资料目录**，登录环境频繁变化本身就是风控信号。
- **人类节奏**：每个动作之间停顿 3–8 秒（随机）；页面滚动一段一段来；不要短时间内打开大量页面。抓数据优先用创作者中心（数据是平台给你的官方出口），少逛社区页面。

## 权限边界：硬线与默认值

- **硬线（任何档位都不放开）**：不自动发布——不打开发布流程、不提交发布、不定时发布；不上传文件、不执行任意脚本；遇到验证码 / 风险提示 / 登录要求停手，由用户本人处理。
- **默认值（可按需放开）**：只读档禁点击 / 输入 / 按键 / 下拉选择，用于学习博主、看数据；需要点进帖子、翻页、站内操作时，由用户明确授权后切到测试档（`browser-mode test`），测完切回。测试档屏蔽创作者中心域名（发布入口），所以**测试档下登录检查改用 `https://www.xiaohongshu.com/`**，看右上角是否已登录。
- 没有授权就别在聊天里让 agent 自己去开 Bash 或 `bypassPermissions`：那会连硬线一起拆掉。该走的是工作台界面里的受控任务（准备浏览器、核实主页、采集）。

## 后台有头只读核实（可选）

后台组件只负责「竞品对标」单账号的主页核实、头像元素局部截图与最多 5 篇主页可见笔记的只读字段；在设置页开启并安装后，确定字段由本地浏览器读取，不调用模型；不判断爆款、不代替深度拆解。它始终有头：首次登录、验证码、操作频繁等情况保留可见窗口，用户本人操作；核对小红书号一致后**尝试**最小化，可能因系统限制回退到可见模式，不保证不会抢焦点。没有读到唯一的当前账号小红书号时不继续采集，不依据旧 `browser.json` 猜身份。agent 进行发布/评论或其他 MCP 浏览器任务前，工作台先关闭后台窗口并释放同账号资料；下次只读任务再打开。外部浏览器占用资料时先请用户关闭，不删除锁文件或复制登录数据。收件箱/非 Playwright 模式不强行替换浏览器。关闭后台组件时可由 agent 按 `benchmark.md` 的观察检查点流程逐条补齐；此流程要求当前账号的小红书号已填写且与此刻浏览器登录账号一致，不能以旧的 `browser.json` 代替核验。

## 每个账号一个浏览器

- CLI 模式下启用 Playwright 浏览器控制后，**每个工作台账号都有自己的一份浏览器资料**（`browser-profiles/<账号id>/`）。你打开的浏览器自动就是当前账号的，登录状态与其他账号互不影响。
- 用 Claude in Chrome，或收件箱模式下用你自带的浏览器时，所有账号共用一个浏览器。这时更要严格执行下面的「账号核对」。

## 登录检查

> 员工在网页「账号管理」点「登录账号」时，由工作台自己的浏览器打开创作者中心并等本人扫码 / 完成验证（v0.8.2 起），不经过 agent。agent 不需要、也不应该自己去打开浏览器帮员工登录。下面的步骤只在 agent 做采集前核对登录状态时使用。

1. 打开 `https://creator.xiaohongshu.com/`。
2. 首次导航若显示登录页，**先等待 10–15 秒并重新获取页面快照**（总计不超过 30 秒），排除页面加载或登录跳转延迟；不要只凭首个快照就把 `browser.json` 标为未登录。复查仍为登录页时停下，请用户在当前工作台浏览器窗口里亲自登录（扫码或验证码由用户本人完成）。每 15 秒检查一次，最多等 5 分钟；**超时就不要继续等**——先交付不依赖登录的部分，说明卡点后结束本轮。
3. **频繁掉线的处理**：登录态失效可能有多种原因，不能仅凭掉线判断是风控。若页面明确出现验证码、操作频繁或风险提示，立即停止并告知用户；在原因不明时建议降低操作频率，不保证任何做法能避免风控。
4. 登录后读取页面上的**昵称和小红书号**。
5. 写入当前账号数据目录下的 `browser.json`：

```json
{ "loggedIn": true, "nickname": "昵称", "xhsId": "小红书号", "checkedAt": "2026-10-15T10:00:00.000Z" }
```

没登录上就写 `"loggedIn": false`。

## 账号核对（每次操作前都要做）

用登录检查读到的小红书号，和提示词「当前账号」中的小红书号比较：

| 情况 | 处理 |
|---|---|
| 一致 | 继续执行 |
| 当前账号没有填写小红书号 | 继续执行，并在回复中提醒用户：到「账号管理」里补上小红书号（填写后才能防止用错号） |
| **不一致** | **立即停止，不做任何操作**。在回复中说明：浏览器登录的是哪个号、当前账号应该是哪个号。发布任务按 `publish.md` 标记为 `failed` |

## 其他

- 原 MCP agent 任务结束时浏览器随之关闭；可选后台只读组件会保留同账号的有头窗口（可能最小化），直到 MCP 任务接管、用户关闭后台读取或服务停止。登录状态保存在各自资料里，但平台可能要求重新登录。
- 截图、页面快照等临时文件只放在工作台指定的输出目录，不要写到数据目录其他位置。
