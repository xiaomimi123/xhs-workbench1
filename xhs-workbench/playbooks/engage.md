# 评论私信操作手册

**先读 `README.md` 的「账号安全规则」。** 回复代表账号形象，默认只起草、由用户确认后再发送。

## 数据位置

当前账号数据目录下 `engage/items.json`：

```json
{
  "items": [
    {
      "id": "e_xxx",
      "type": "comment | dm",
      "noteTitle": "评论所在的笔记标题（私信可留空）",
      "noteUrl": "笔记链接",
      "user": "对方昵称",
      "content": "评论 / 私信内容",
      "time": "2026-10-15T08:30:00.000Z",
      "status": "new | drafted | approved | sent | ignored | failed",
      "draft": "回复草稿",
      "sentAt": "发送时间",
      "error": "发送失败原因"
    }
  ]
}
```

状态流转：`new`（刚抓到）→ `drafted`（你起草了）→ `approved`（用户确认）→ `sent` / `failed`（你发送后）。用户也可能改为 `ignored`。

## 检查新消息

1. 用浏览器控制工具打开创作者中心的评论管理 / 消息页面（未登录时请用户登录，规则同 `publish.md`）。
2. 读取最近的新评论和私信。私信优先读会话列表里的预览，**不要逐个点开会话**（会被标为已读，用户可能还没看过）；需要完整内容时在回复中说明，由用户决定。**去重**：同一用户、同一内容、同一笔记已经在 `items.json` 里的不要重复添加。
3. 新条目追加到 `items` 开头，`id` 用 `e_` + 任意字母数字，`status` 为 `new`。
4. 没有浏览器能力时：请用户把评论区 / 私信截图发给你，或直接在对话里粘贴内容，你再整理写入。
5. 不需要回复的（纯表情、广告、明显的引战）可以直接把 `status` 设为 `ignored`，并在回复中说明。

## 起草回复

1. 先读知识库 `品牌口径/`（尤其是评论区回复口径）、`账号定位/`（人设语气）。
2. 每条写进 `draft`，`status` 改为 `drafted`。
3. 要求：
   - 像真人：口语化，针对对方说的内容回应，不要每条都一样。
   - 简短：评论回复一般 15-60 字。
   - 合规：不引导站外（微信、淘宝等），不承诺效果，不用绝对化用语（词表见 `web/lint.js`）。
   - 负面评论：先共情、再解释，不争辩；涉及售后 / 投诉的，建议用户本人处理，并在回复中标注。
4. 回复用户：起草了几条、哪些需要特别注意。

## 发送

- **只发送 `status` 为 `approved` 的条目，内容严格使用 `draft`，不要改写。**
- 用户开启了自动发送（任务提示里会说明）时，才可以发送你自己起草的回复，且不超过提示中给出的条数上限。
- 每条之间停顿 10-30 秒（随机），模拟真人节奏。
- 每条发送后立即更新：成功 → `sent` + `sentAt`；失败 → `failed` + `error`。
- 出现"操作频繁"等风控提示：立即停止，剩余条目保持原状态，告诉用户。

## 页面经验（2026-10 实测，页面改版后可能失效）

- 回复评论：打开 `noteUrl` 对应的笔记页，找到对方的评论，先确认下面没有作者的回复（避免重复回复），再点该评论的「回复」，确认输入框显示「回复 <对方昵称>」后再输入。
- 发送后在评论区确认出现带「作者」标识的回复，再更新状态。

## 沉淀

发现高频问题时，建议用户（或在用户要求时）整理到知识库 `品牌口径/评论区回复口径.md`。
