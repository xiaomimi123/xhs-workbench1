## 未发布 · 升级机制

- 数据目录新增版本记录（`config/version.json`：程序版本、数据格式版本、升级历史）；版本变化时启动前自动备份（`upgrade-*.zip`），再按序执行迁移；迁移失败不推进版本、保留备份并在网页显示原因，下次启动重试；备份失败则不迁移
- 数据来自更新版本时（程序被换成了旧包）拒绝启动，不改动任何数据
- 新增 `upgrade --check` 与 `upgrade --package <zip> [--yes]`：预检安装包（完整性、版本、路径安全），备份后替换技能包，旧版本保留为 `.bak-<版本>`，失败自动回滚
- `setup` 在全新数据目录里立刻登记版本，避免服务误判为旧版遗留数据
- 版本号集中到 `server/version.mjs`；「连接与设置」显示版本、数据格式与最近升级记录
- 自动化测试新增 17 项（upgrade）

## 未发布 · 环境自检与安装流程

- 新增 `doctor [--json]`：检查 Node、数据目录、ffmpeg/ffprobe、Agent 连接，缺项直接给出按本机包管理器（winget / choco / scoop / brew）选好的安装命令，最后一行 `RESULT: ok | action-needed | blocked`，agent 照输出执行即可
- ffmpeg / ffprobe 改为先查 PATH、再查各系统常见安装目录（含 Windows 的 WinGet、用户目录解压位），刚装完未重开终端也能找到
- SKILL.md 安装流程改为：检查 Node → `doctor` → 初始化 → 启动；明确“装可选依赖前先告知影响与体积、需要密码/管理员权限的步骤由用户本人操作、装完必须用 doctor 复核”
- 修复打包脚本：Node 22+ 不再接受目录作为 `--test` 参数，改为显式列出测试文件，失败时输出具体失败项
- 自动化测试新增 8 项（doctor）

## 未发布 · APIMart 提交失败诊断

- 生图提交失败不再丢失原因：记录失败阶段（connect/http/respond）、HTTP 状态、请求编号（x-request-id/cf-ray）和脱敏后的网关返回（自动替换 API Key 为 `***`），诊断信息随任务落盘，重启后仍可查看
- 区分「明确拒绝」与「结果不确定」：网关 4xx（408 除外）视为已拒单、未创建远端任务，可直接修正参数重试；断网、5xx、响应缺任务编号等记为「不确定」，提示先到 APIMart 控制台核对任务编号，避免重复生成重复计费
- 已有诊断的任务再次刷新时保留原始失败原因，只补充本轮结论，不再被固定文案覆盖
- 自动化测试新增 4 项回归（拒单、断连、缺编号、查询 404）
